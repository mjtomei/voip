# Voice operator

Call a persistent Codex session from a phone. Workers can leave messages, request
prepared outgoing calls, and schedule conversations. Projects own their prompts,
notes and mailboxes; each named session has its own conversation and audio path.

This is an experimental Linux application using Codex native realtime voice,
Twilio Programmable Voice/SIP, Baresip and PipeWire. It is intended for a trusted
personal installation. See [security and data handling](SECURITY.md),
[current architecture](ARCHITECTURE.md), and [known limitations](TESTING.md#known-limitations).
No license is included.

The [reference installation](docs/REFERENCE-SETUP.md) includes the full operator
protocol and an external-project daily-meeting workflow with fictional people,
paths and phone numbers. [Consolidation inventory](docs/CONSOLIDATION.md) maps the
retained features to their implementation and tests.

## Start with the clean container tests

Requires Docker on Linux. The build downloads system packages, pinned Python/Node
dependencies, patched Baresip and the local speech-recognition model. The test run
requires no API keys, phone numbers, account login or host audio devices.

```bash
docker build --target test -t voice-operator:test .
docker network create --internal voice-test-isolated
docker run --name voice-tests --network voice-test-isolated voice-operator:test
docker cp voice-tests:/opt/voip/state ./test-evidence
docker rm voice-tests
docker network rm voice-test-isolated
```

The image starts its own PipeWire server and exercises Python/Node integration,
real local WebRTC, virtual audio routing, and synthetic PIN speech verified with
STT. Native Codex and handset tests have separate prerequisites and commands in
[TESTING.md](TESTING.md); their historical results are not clean-install proof.
See [current validation results](docs/RELEASE-VALIDATION.md) for verified boundaries
and remaining failures.

## Install locally

The supported starting point is Ubuntu 24.04, Python 3.11+, Node 22 for tests,
tmux and a running PipeWire/Pulse server. The builder needs build-essential,
cmake, pkg-config, libssl-dev, libpulse-dev, pulseaudio-utils, patch and curl.
Install prerequisites through your system package manager, then:

```bash
python3 scripts/install.py --audio
# Optional local TTS/STT acceptance tools:
python3 scripts/install.py --test-tools
```

`~/.local/bin/voip` points to this checkout's managed Python environment and works
from any directory. Keep the checkout in place. Installation neither deploys
provider resources nor starts calling services. For a containerized phone service
connected to host Codex, follow [CONTAINERS.md](docs/CONTAINERS.md).

## Configure an installation

Choose a private workspace, an existing Twilio voice number, and the allowed
recipient's number. The numbers below are fictional; replace them before deploying.

```bash
voip --root /absolute/path/to/voice-workspace init \
  --number +12025550100 --recipient alice --destination +12025550101
```

This writes `server.toml`, `recipients.toml`, `sessions/default.toml` and an empty
schedule file. It does not generate or deliver a PIN. Session tool access defaults
to `read-only`; choose `workspace-write` or `danger-full-access` explicitly in
`[operator].permissions` or a session's `permissions` setting. These headless
profiles use approval policy `never`; they cannot show an interactive approval.

The [configuration example index](examples/README.md) maps every editable local
configuration file to its template, including credentials and container overrides,
and identifies the SIP, audio and systemd files generated by setup commands.

Configure `TWILIO_API_KEY_SID` and `TWILIO_API_KEY_SECRET` in the process environment
or a mode-0600 literal KEY=value file referenced by `[service].credentials_file`.
Values are not shell-expanded. `TWILIO_SID`/`TWILIO_SECRET` are compatible aliases.
No service sources a shell profile. Use a Twilio key authorized to manage this
installation's Functions, Assets, SIP, calls and Sync receipts.

Generate and privately deliver a PIN, then inspect the deployment plan:

```bash
# Private terminal only: prints the new PIN once. Never capture it in an agent log.
voip --root /absolute/path/to/voice-workspace pin generate alice --delivery print
voip --root /absolute/path/to/voice-workspace config check
voip --root /absolute/path/to/voice-workspace config show --json
voip --root /absolute/path/to/voice-workspace config plan --hosted-only
voip --root /absolute/path/to/voice-workspace config apply --hosted-only
```

Alternatively use [confirmed telephone PIN delivery](docs/PIN-DELIVERY.md).
Deployment configures an existing number; it does not buy one. `--hosted-only`
deploys provider handlers without installing/restarting local services. The
legacy full `config apply` also manages per-component systemd services; choose
one supervision method, never run it alongside the foreground/container stack.

Start the host Codex daemon with your existing login, initialize once and start:

```bash
codex app-server daemon start
voip --root /absolute/path/to/voice-workspace operator init
voip --root /absolute/path/to/voice-workspace service start
voip --root /absolute/path/to/voice-workspace doctor --live
voip --root /absolute/path/to/voice-workspace status --json
```

`service enable` installs the stack as a user startup service; `service disable`
disables/stops that service. `service stop` stops a foreground/background stack.
For containers use Compose's lifecycle commands. See [operations](docs/OPERATIONS.md).

## Three workflows

**Call an operator.** Dial the configured Twilio number from an allowed phone and
enter that person's PIN. A configured `extension#` before the PIN selects an
allowed session; ordinary PIN entry reaches the person's default. Calls preserve
the selected conversation. `*1#` reconnects voice, `*2#` reloads the same session,
and `*3#` selects a fresh conversation. Full reset needs local Codex metadata;
container prerequisites are explicit in its guide.

Optional [directory extensions](docs/DIRECTORY-EXTENSIONS.md) discover active tmux
projects, infer home-based sessions' project directories from their names, and
assign numbers from the branching directory tree. Each directory keeps its own
operator conversation; manual extensions retain priority.

**Request a prepared conversation.** The agenda is loaded before the phone rings:

```bash
voip --root /absolute/path/to/voice-workspace --session default request call \
  --recipient alice --request-key review-20261001 --reason 'Review the project plan' \
  --from worker --file /absolute/path/to/agenda.txt --json
voip --root /absolute/path/to/voice-workspace request status review-20261001 --json
```

The first command queues work; it does not establish ringing, connection or
completion. Reuse its stable key for retries. `request cancel KEY` withdraws the
request; inspect cleanup settlement. Messages can also be posted independently:
`mailbox post --recipient alice --from worker --subject TEXT --key KEY --file FILE`.
Reading a message does not address it; resolving it requires an actual outcome.

**Schedule a recurring meeting.** Adapt [schedules.toml.example](schedules.toml.example),
set the session, recipient, agenda and IANA timezone, and explicitly enable it.
Run `schedule next --count 3` before enabling the dispatcher. Scheduled requests
use the same preparation, priority, admission and retry logic as manual calls.
Missed offline occurrences are skipped and counted by default.
